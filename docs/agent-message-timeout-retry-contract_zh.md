# Agent 消息超时与重试契约

本文档定义 ask 驱动 agent 交付的运行时/消息契约。

## 1. 启动失败不得留下静默运行中的 Job

如果 provider job 在启动时无法绑定到可用的运行时，执行路径不得将 job 留在静默的 `running` 状态。

规则：

- 缺失运行时上下文、缺失 provider session、后端绑定失败和等效引导失败必须表现为终端执行失败信号
- 这些失败必须可用于正常的重试策略评估
- 系统不得将此类 job 停放在永不产生终端决策的被动状态

## 2. 超时意味着检查，而非盲目失败

当运行中的 attempt 达到完成超时但未确认终端回复时：

- job 状态变为 `incomplete`
- 调用者收到标准检查通知回复
- 通知必须告知调用者任务可能仍在目标 agent session 中运行
- 通知必须指引调用者/操作者在决定继续或重试前检查活跃 agent 状态

超时不被视为自动 provider/API 失败。

## 3. 重试必须在上下文已存在时保留上下文

自动或手动重试在同一逻辑消息谱系中创建新的 attempt。

重试主体策略：

- 如果先前的 attempt 已进入 provider 上下文，重试发送 `continue`
- 如果先前的 attempt 从未进入 provider 上下文，重试重放原始请求主体

Provider 上下文进入由先前的终端证据确定，例如：

- `anchor_seen`
- `reply_started`
- 已标记为 `continue` 的重试谱系

## 4. 超时默认不自动重试

仅超时不自动重新提交任务主体。

原因：

- 某些 agent 执行确实是长时间运行的
- 盲目重试浪费工作，可能错误地分叉目标 session

超时后的第一个系统响应是检查通知，而非自动重放。
