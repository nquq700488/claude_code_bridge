# CCB 配置与布局契约

## 1. 目的

本文档定义 `ccb_source` 中项目配置、窗格布局和 tmux 展示的面向用户的不漂移契约。

它是以下内容的权威设计锚点：

- `.ccb/ccb.config`
- 紧凑布局语法
- 默认引导布局生成
- 窗格命名和窗格颜色身份
- 项目 UI 的 tmux 分割大小规则

## 2. 面向用户的配置契约

- `.ccb/ccb.config` 是唯一的面向用户的项目配置文件。
- 新项目必须引导 `.ccb/ccb.config`。
- 用户帮助文本、验证输出、诊断和文档必须指向 `.ccb/ccb.config`。
- `.ccb/config.yaml` 不属于契约的一部分，当前代码不得读取或写入。

## 3. 紧凑布局语法

主要配置格式是紧凑文本。

叶令牌：

- `cmd`
- `agent_name:provider`

操作符：

- `;`
  - 水平分割，从左到右
- `,`
  - 垂直分割，从上到下
- `(...)`
  - 显式分组

操作符优先级：

1. `,`
2. `;`

示例：

- `cmd; agent1:codex`
- `cmd; agent1:codex, agent2:claude`
- `cmd, agent1:codex; agent2:codex, agent3:claude`
- `cmd, agent1:codex; agent2:codex, (agent3:claude; agent4:gemini)`

## 4. 语义规则

- `cmd` 是保留的，不得声明 provider。
- 每个配置的 agent 必须在布局中恰好出现一次。
- `cmd` 最多出现一次。
- 当 `cmd` 启用时，`cmd` 必须是布局遍历中的第一个叶，以便调用窗格保持为命令窗格锚点。
- 紧凑配置叶顺序定义 `default_agents`。
- 丰富的 `ccb.config` 格式可单独定义 agent，但仍必须提供与相同叶规则兼容的 `layout`。

## 5. 默认布局契约

引导必须对所有可见窗格生成平衡的两列布局。

对于 `cmd + N agents`：

- 1 agent: `cmd; agent1`
- 2 agents: `cmd; agent1, agent2`
- 3 agents: `cmd, agent1; agent2, agent3`
- 4 agents: `cmd, agent1; agent2, agent3, agent4`

通用规则：

- 将完整窗格列表分成左右两半
- 将每一半垂直堆叠
- 通过根据后代叶计数调整每个分割来保持窗格区域均匀

## 6. Tmux 布局执行契约

- 当前窗格是 `cmd` 锚点窗格。
- 布局执行必须将配置的布局裁剪到请求的前景 agent 子集加 `cmd`。
- 布局执行必须首先从 `parse -> prune -> render` 构建规范化的可见布局计划，该规范化渲染是可见布局签名。
- 布局执行必须在裁剪后保留配置布局的相对结构。
- 递归分割百分比必须从叶计数比率计算，而非硬编码重复的 `50%` 分割。
- 窗格裁剪不得静默重排 agent。
- 增量式就地分割在已物化的项目命名空间之上不是实现不同可见布局签名的有效方式。
- 当期望的可见布局签名变更时，启动必须在重新物化 tmux 窗格之前重新创建项目命名空间。

## 7. 窗格展示契约

- `.ccb/ccb.config` 逻辑叶名称是窗格显示名称的唯一权威。
- 窗格标题必须是精确的逻辑名称：
  - `cmd`
  - `agent1`, `agent2`, ...
- 窗格边框标签必须显示逻辑窗格名称，而非 tmux 窗格编号。
- Provider 特定的窗格标记（如 `CCB-agent1-...`）仅是内部运行时证据：
  - 它们可能持久化在 provider session 文件中
  - 它们不得覆盖项目命名空间 UI 中的窗格标题、窗格头部或焦点标签
- Tmux 窗格用户选项和可见标题必须在项目拥有的窗格被复用或重新绑定时调和回配置的逻辑名称。
- 命令窗格和 agent 窗格必须具有稳定、不同的颜色身份。
- 窗格样式是 session 范围的 CCB UI 状态，不得永久覆盖不相关的用户 tmux 主题。

## 8. 项目命名空间 UI 契约

- 项目拥有的 tmux socket/session 负责自己的主题和窗格头部渲染。
- 项目 UI 正确性不得依赖于调用 shell 是否已在某个外部 tmux 服务器内部。
- 命名空间创建或复用必须在项目拥有的 socket 上重新应用 session 范围的 CCB tmux 选项。
- 当项目拥有的窗格死亡且守护进程选择命名空间级恢复时，它必须重新创建并重新投影配置的布局，使每个逻辑窗格回到其规范位置。
- 命名空间 `layout_version` 是可见窗格拓扑和 tmux UI 展示的兼容性键：
  - 当存储的命名空间布局版本与当前代码契约不同时，必须重新创建项目命名空间
  - 重新创建命名空间是陈旧窗格几何或陈旧 session 范围 UI 选项的首选修复路径
- 命名空间状态还必须跟踪从 `.ccb/ccb.config` 前景裁剪后派生的当前可见布局签名。
- 如果存储的可见布局签名与当前前景启动的期望可见布局签名不同，必须重新创建命名空间，而非尝试就地修补几何。

## 9. 更新纪律

- 如果 `.ccb/ccb.config` 语法变更，在同一次补丁中更新本文档。
- 如果引导布局默认值变更，在同一次补丁中更新本文档。
- 如果窗格命名、分割大小或窗格主题规则发生重大变更，在同一次补丁中更新本文档。
